# AI 안내: 학교 운영 보안 절차를 선생님과 하나씩 정하기 (`dcheck ops`)

학교에서 쓰는 앱(학생·학부모·교직원 정보를 다루는 앱)은 교육(지원)청 개인정보 자체점검 공문의 붙임2(개인정보보호 자체 점검표)와 붙임3(개인정보보호위원회 외부 접속 가능 시스템 점검항목)으로 점검을 받아요. 그 질문 가운데에는 코드 한 줄로 끝나지 않는 까다로운 절차가 많아요. 로그인 실패 잠금, 관리자 2단계 인증, 자동 로그아웃, DB 직접 접속 IP 제한, 접속기록 보관, 권한 이력, 백업, 사고 대응 같은 것들이에요.

이 안내의 목적은 **고치게 만드는 것이 아니라, 선생님이 알고 고르게 돕는 것**이에요. 점검 마크의 조건도 아니에요.

## 순서

1. 앱 폴더에서 `dcheck ops` 를 실행해요. 지난 `scan` 결과가 있으면 함께 씁니다.
   - Supabase 를 쓰는 앱이고 선생님이 원하면 운영 설정도 읽을 수 있어요: 선생님이 Supabase 대시보드 Account > Access Tokens 에서 만든 토큰을 `SUPABASE_ACCESS_TOKEN` 환경 변수로 넣고 `dcheck ops --supabase-config` 를 실행해요. 이 명령은 api.supabase.com 에 **읽기 요청만** 보내고 설정을 바꾸지 않아요. 토큰 값을 대화·파일·명령 기록에 남기지 마세요. 선생님이 토큰을 대화에 붙여 넣으려 하면 막고, 컴퓨터의 숨김 입력이나 환경 변수로 넣게 안내하세요.
   - 토큰은 앱 저장소의 `.env*` 파일에 넣지 않아요(커밋되거나 `NEXT_PUBLIC_`·`VITE_` 변수로 화면 코드에 섞일 수 있어요). 셸 설정 파일에 `export` 로 남기지 말고 그 명령에만 넣어요. 만들 때 만료 기간을 고를 수 있으면 짧게 하고, 다 쓰면 대시보드에서 지워요. 화면에 나오는 프로젝트 번호가 선생님 앱이 맞는지 확인해요.
   - 토큰이 없으면 읽지 않은 채로 진행하고, 그 항목은 "확인 못 함"으로 둔 뒤 대시보드에서 볼 곳을 알려 줘요.
2. `.dorms-check/OPS.md` 를 읽고, **한 번에 한두 항목씩** 선생님께 설명해요. 항목마다 이 네 가지를 쉬운 말로 말해요.
   - 지금 상태(도구가 본 근거와 못 본 것)
   - 왜 필요한지(학교 서류의 어느 칸, 어떤 기준에서 묻는지)
   - 켜면 생기는 일(DB 재시작, 현장 기기 로그아웃, IP 가 바뀌면 목록 수정, 잠긴 계정을 풀어 줄 사람 등)
   - 할지 말지 묻는 질문(`ask`)
3. 선생님 답을 그대로 기록해요.
   - 하기로 함: `dcheck ops decide --id <항목> --choice do`
   - 하지 않기로 함: `dcheck ops decide --id <항목> --choice skip --reason "<학교 서류에 쓸 사유>"` (OPS.md 의 사유 예시를 보여 주되, 선생님 상황에 맞는 문장을 선생님이 정해요)
   - 이미 함: `--choice done --reason "<무엇으로 했는지>"`
   - 나중에: `--choice later`
4. "하기로 함" 항목은 **따로 선생님 확인을 받은 뒤** 구현해요. 구현 전에 바뀔 파일·설정과 부작용을 다시 보여 주세요.
   - 운영 설정을 바꾸는 일(SSL 강제, 네트워크 제한, 세션 시간, 비밀번호 기준, 사이트 주소)은 대시보드에서 선생님이 직접 바꾸거나, 선생님이 명시적으로 맡겼을 때만 바꿔요. DB 재시작이 생기는 설정은 학생이 쓰지 않는 시간에 해요.
   - 코드로 만드는 일(잠금·접속기록·권한 이력·내려받기 사유·요청 횟수 제한·2단계 인증 화면)은 기존 구조를 먼저 읽고 마이그레이션·서버 함수·관리자 화면을 같이 만들어요. 기록 표는 화면·공개 키로 고치거나 지울 수 없게 막아요. 기록에 학생 이름·연락처 값을 그대로 넣지 마세요.
   - 계정 정리는 지우지 말고 로그인 차단부터(되돌릴 수 있게) 해요.
5. 끝나면 `dcheck ops` 를 다시 실행하고, `.dorms-check/SCHOOL-SELFCHECK.md`(학교 서류 대응표 초안)를 보여 줘요. "O(확인 후)" 칸도 선생님이 근거를 한 번 보고 정하게 하세요. X 칸 사유는 선생님이 남긴 문장 그대로예요.

## 지킬 것

- 한꺼번에 모든 항목을 고치자고 하지 않아요. 학교마다 사정(담당 인력·현장 기기·요금제)이 달라 X 가 맞는 항목도 있어요.
- "법 위반"처럼 겁주는 말 대신, 근거(고시 조문·점검표 번호)와 실제로 생기는 위험을 함께 말해요. 법률 판단이 필요하면 학교 개인정보 담당자·교육청에 확인하라고 안내해요.
- 도구가 못 본 것을 "갖춤"으로 바꾸지 않아요. 흔적(코드에 그런 이름이 있음)은 동작한다는 증명이 아니에요.
- 운영 DB 데이터를 지우거나, 운영 서버에 공격 요청을 보내지 않아요.
- 결정 기록(`.dorms-check/ops-decisions.json`)과 서류 초안에는 사람 이름·연락처·IP 주소 원문을 적지 않아요.
