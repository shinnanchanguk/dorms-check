# ai-review 지시문: 심층 보안 점검 (dcheck audit)

선생님이 "정밀 보안 점검", "보안 감사", "제대로 다 봐 줘", "보안 보고서"처럼 **명시적으로** 요청할 때만 이 흐름을 씁니다. 그냥 "보안 괜찮아?"라고 물으면 기본 점검(`scan`)과 필요한 부분만 답하고, 이 흐름을 혼자 시작하지 않습니다. 애매하면 한 번만 물어보세요: "코드를 처음부터 끝까지 나눠 보는 심층 점검을 할까요, 아니면 기본 점검으로 충분할까요?"

이 흐름은 cloudflare/security-audit-skill(MIT)의 6단계 감사를 교사 앱에 맞게 옮긴 것입니다. 기본 점검이 이미 보는 것(보안 헤더·HTTPS·공개된 비밀값·익명 키 DB 읽기)은 다시 보지 않고, 코드 안에서만 보이는 권한 우회·업무 규칙·AI 기능·요금 고갈 같은 것을 봅니다.

## 지킬 원칙

- **경계와 결과가 있어야 위험입니다.** 누가(더 낮은 권한의 사람), 무엇을 보내서, 어떤 확인을 넘어, 누구의 무엇에 영향을 줬는지 적지 못하면 위험이 아니라 권고입니다.
- **찾는 사람과 검증하는 사람을 나눕니다.** 후보를 찾은 에이전트는 그 후보를 검증하지 않습니다. 검증하는 쪽은 반박하려고 처음부터 다시 읽습니다. 도구가 같은 담당자 ID 로 검증하려 하면 거부합니다.
- **판정은 셋입니다.** 확인한 위험(confirmed, 심각도 있음), 미확인(needs_validation, 심각도 없음, 막힌 사실과 확인 방법 필수), 기각(rejected).
- **배포된 서버에 공격 요청을 보내지 않습니다.** 코드 읽기와 내 컴퓨터 안의 가짜 데이터 시험만 합니다. 실제 회원 계정·운영 DB·유료 API 는 쓰지 않습니다. 저장소 밖 사실(대시보드 설정 등)이 결정적이면 미확인으로 남기고 선생님이 직접 볼 곳을 적습니다.
- **앱 코드 실행은 운영체제가 막아 줄 때만.** 네트워크 차단·빈 환경변수·읽기 전용 원본·scratch 만 쓰기·자원 제한을 강제할 수 없으면 실행하지 말고 미확인으로 남깁니다.
- **한 번에 다 볼 수 없습니다.** 범위표에 본 것과 못 본 것을 남기고, 다음 점검은 그 빈칸부터 봅니다.

## 순서

1. `dcheck scan` 을 먼저 돌려 두면 계획이 그 결과를 겹치지 않게 반영합니다(필수는 아님).
2. `dcheck audit plan --profile quick|standard|deep [--scope <경로>] [--budget <N>]`
   - quick: 찾기 한 차례 + 범위 비평 한 번. 작은 앱·첫 점검. 부분 점검으로 보고합니다.
   - standard: 빈칸이 없을 때까지 찾기·비평을 되풀이하고 마지막에 깨끗한 비평 한 번 더.
   - deep: 파일 단위로 나누고 반박 검증과 최종 확인을 따로 둡니다.
   - 결과는 `.dorms-check/audit/run-N` 에 쓰입니다. `.dorms-check` 가 `.gitignore` 에 없으면 홈 폴더(`~/.dorms-check-audit/`)에 씁니다. 약점 설명이 담기므로 커밋하지 않습니다.
3. **정찰**: `architecture.md` 를 1,000 단어 안으로 채웁니다(누가 쓰는지, 무엇을 지키는지, 신뢰 경계와 가장 강한 통제의 코드 위치).
4. **찾기**: `AUDIT-PLAN.md` 의 묶음마다 `dcheck audit prompt --role hunter --agent <ID> --group <번호>` 로 지시문을 받아 서로 다른 에이전트에게 맡깁니다. 하위 에이전트가 없는 AI 라면 묶음 하나씩 새 대화에서 처리합니다.
5. **병합**: 돌아온 JSON 을 파일로 저장하고 `dcheck audit merge --agent <ID> --in <파일>`. 형식이 틀린 단위는 다시 맡길 수 있게 예정으로 돌아갑니다.
6. **범위 비평**: `dcheck audit prompt --role critic --agent <새 ID>` → 결과를 같은 merge 명령으로.
7. **반박 검증**: 후보마다 찾지 않은 새 에이전트에게 `dcheck audit prompt --role verifier --agent <ID> --fingerprint <지문>` → `dcheck audit record --agent <ID> --in <파일>`.
8. **최종 확인**(quick 이 아니면): 확인한 위험·미확인 기록마다 또 다른 새 에이전트가 기록 자체를 다시 확인합니다. `{"decision":"verified","fingerprint":"..."}` 또는 `{"decision":"replace","reason":"...","record":{...}}`. 판정이 세지거나 뜻이 바뀌는 교체는 또 다른 새 담당자가 verified 를 보내야 적용됩니다.
9. `dcheck audit check` → `dcheck audit report`. 보고서는 `AUDIT.md` 입니다.

## 선생님께 설명할 때

- 확인한 위험은 "무엇이, 누구에게, 어떻게"를 쉬운 말로 먼저 말하고, 가장 작은 수정과 함께 알려 줍니다.
- 미확인은 실패가 아닙니다. 선생님이 대시보드에서 직접 볼 곳(메뉴 이름까지)을 알려 줍니다.
- 기각한 주장은 굳이 설명하지 않습니다. 같은 오해가 다시 나오면 그때 이유를 말합니다.
- 범위 요약의 미룸·범위 밖을 숨기지 않습니다. "이번에 이만큼 봤고, 이건 아직 못 봤어요"로 말합니다.
- 비밀값을 찾으면 값을 옮겨 적지 말고 파일 위치와 변수 이름만 말하고, 재발급(교체)을 권합니다.
